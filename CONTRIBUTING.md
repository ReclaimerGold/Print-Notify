# Contributing to Print-Notify

Thanks for helping out! This guide covers the dev loop, the conventions the code
follows, and the two things you'll most likely touch: **adding a source** and
**rendering bitmaps** for the receipt.

## Dev setup

```bash
npm install
cp .env.example .env       # enable whatever sources you're testing
npm run dev                # dashboard on http://localhost:3000
npm run typecheck          # tsc --noEmit — keep this green
```

You also need **Python 3 + Pillow** (`pip install pillow`) for the bitmap
renderers in `scripts/`.

### Test without a printer

Set `PRINTER_DRY_RUN=true`. Instead of printing, the app writes the raw ESC/POS
bytes to `data/last-receipt.bin`. To *see* a receipt, render it to a PNG (this is
the same path the web preview uses) and open it:

```ts
import { buildDigestBlocks } from './src/digest.js';
import { receiptImage } from './src/bitmap.js';
const png = await receiptImage(await buildDigestBlocks('Test', items), 42);
```

For unit-ish checks, mock `globalThis.fetch` and call a source's `fetch()`
directly — see the ad-hoc patterns used during development.

## Conventions

- **TypeScript, strict, ESM.** Imports use the `.js` extension (e.g.
  `./config.js`) even for `.ts` files — that's required by the ESM/tsx setup.
- **Match the surrounding style** — small focused modules, terse comments that
  explain *why*, no framework churn. Keep runtime deps minimal (currently just
  express, node-cron, node-thermal-printer, dotenv, zod).
- **Config lives in `src/config.ts`**, driven by `.env`. A feature/source is
  "enabled" only when its config is present — never hard-fail on a missing key.
- Keep `npm run typecheck` clean before opening a PR.

## Adding a source

A source is one file that returns normalized items. The digest, dedupe,
scheduler, and dashboard pick it up automatically.

1. Create `src/sources/<name>.ts` exporting a `Source`:

   ```ts
   import { config } from '../config.js';
   import type { Source, NotificationItem } from './types.js';

   export const mySource: Source = {
     name: 'my-source',
     enabled: Boolean(config.sources.mySource?.enabled),
     async fetch(): Promise<NotificationItem[]> {
       // ...fetch + map to NotificationItem[]
     },
   };
   ```

2. Add any config to `src/config.ts` (gate `enabled` on it).
3. Register it in `src/sources/index.ts` (`sources` array).

### `NotificationItem` fields

| field | purpose |
|-------|---------|
| `id` | stable unique id (used to dedupe the urgent poll) |
| `source` | **also the digest section name** — items are grouped by this, and the header is `source.toUpperCase()` (e.g. a Google Tasks list titled "Groceries" → its own `GROCERIES` section) |
| `title` / `detail` | main text + secondary line |
| `severity` | `info` \| `notice` \| `urgent` (only `urgent` triggers the ad-hoc poll print) |
| `image` | absolute path to a bitmap printed above the item (e.g. a weather icon) |
| `checked` | if set, the item renders as a pen box `[ ]` / `[x]` |
| `timestamp` | ms epoch; used for global ordering (stable sort preserves per-source order for equal timestamps) |

## The block model (print === preview)

Everything that prints is first turned into an ordered list of **blocks** in
`src/digest.ts`:

```ts
type Block =
  | { type: 'image'; path: string; align?: 'center' | 'left' }
  | { type: 'text'; text: string; bold?: boolean; align?: 'center' | 'left' }
  | { type: 'rule' }
  | { type: 'space' };
```

- `printReceipt(blocks)` sends them to the thermal printer.
- `receiptImage(blocks, chars)` renders them to a PNG (the web preview) via
  `scripts/render_receipt.py`.

**Always go through blocks.** Because both the printer and the preview consume
the same list, anything you add shows up correctly in both. Item-specific layout
lives in `itemBlocks()` (checkboxes, the calendar timeline, news bullets, weather
icon + stats).

## Bitmap rendering

Graphical elements are PNGs generated by Python (Pillow) and printed as ESC/POS
raster. `src/bitmap.ts` bridges TS → Python and **content-caches** every result
in a temp dir, so steady-state prints spawn no subprocesses.

| Helper | Renderer | Used for |
|--------|----------|----------|
| `textImage(text, 'title' \| 'section')` | `scripts/render.py` | bold title, white-on-black section bars |
| `weatherIconPath(group)` | `scripts/gen-weather.py` (pre-generated) | sun/cloud/rain/… icons |
| `forecastImage(days)` | `scripts/render_forecast.py` | the 3-day day/night grid |
| `receiptImage(blocks, chars)` | `scripts/render_receipt.py` | full preview PNG |

The logo is `branding/ferrix-logo-print.png` (regenerate with
`python3 scripts/gen-logo.py` if the source art changes).

### CP437 / text caveat

Native text prints in the printer's **CP437** code page. Only use glyphs that map
to a printable CP437 byte — e.g. bullet `·` → `0xFA`, degree `°` → `0xF8`. Unicode
that doesn't map (ellipsis `…`, ballot box `☐`, block-art beyond `░▒▓█`) is
dropped or mangled. When in doubt, dry-run and inspect the bytes:

```bash
xxd data/last-receipt.bin | grep -iE ' fa | f8 '   # verify your glyph is present
```

Prefer a **bitmap** (via `textImage`/a small drawn PNG) over exotic Unicode.

## Commits & PRs

- Keep commits focused; write a clear imperative subject line.
- Run `npm run typecheck` first.
- If you changed rendering, attach a screenshot of the receipt PNG (dry-run) so
  reviewers can see the output.
- Don't commit secrets — `.env` is gitignored; only edit `.env.example`.

## Project layout

See the tree in [README.md](README.md#how-its-organized). In short:
`src/sources/*` fetch, `src/digest.ts` composes blocks, `src/bitmap.ts` + `scripts/*.py`
render graphics, `src/printer.ts` sends to CUPS, `src/server.ts` serves the dashboard.
